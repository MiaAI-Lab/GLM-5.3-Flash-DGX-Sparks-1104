## DECODE (ranked)

### D1. Replace NCCL all-gathers with your 0108 RoCE ring for the 90 decode gathers — **+6–9% E2E, ~1.5h, low risk**
Mechanism: 4.4 ms of 37 ms round is gathers at ~49 us each; your own ring does 4K–64K in 14–36 us. Even at the conservative end (say 30 us saved × 90 = 2.7 ms) that's ~7% of round time. Decode gathers are small and latency-bound — exactly where your ring won. Wire into the existing PDL chain (gather completion event → routed experts kernel) so no sync is added.
**Gate (GO/KILL):** profiler verify-forward, 2 rows: gather_a+gather_b ≤ 3.2 ms combined (from 4.43) AND greedy hash bit-exact on 3 fixed prompts (prose, code, mixed). KILL if ring latency regresses >NCCL at 8 streams — fall back to NCCL for >4 streams only, keep for 1–4.

### D2. Router: fuse + batch the 45 layer GEMVs into one wide GEMV per call, bf16→keep precision — **+3–5%, ~2h, medium risk**
Mechanism: 2.47 ms vs ~0.6 ms ideal. routerSlices is 288×hidden GEMV per layer, bandwidth-starved at 55 us. Batch all 45 layers' router weights into a single [45×288, hidden] tensor read once (weights are static), then run the select/topk/group-sum per layer from registers/shared. Hidden risk: hc glue may make router inputs non-contiguous per layer — if so, batch only the GEMV, keep select fused as-is.
**Gate:** router ≤ 1.2 ms in profiler AND NLL on 512-token eval set within 0.5% of baseline (router is bf16 math; bit-exactness not required, NLL gate is). KILL if fusion forces a host round-trip per layer.

### D3. Drafter ingest+block onto the PDL/side-stream path, overlap with sampler exchange — **+4–6% prose, ~2h, medium risk**
Mechanism: ~8 ms of the 37 ms round is outside verify-forward; drafter is 5 ms + 3 ms exchange. The block pass (4.5 ms) doesn't depend on the sampler's rank exchange of the *previous* round's tokens until select. Overlap drafter block with sampler exchange on the side stream; PDL-chain the ingest. Prose (2.05 tok/round) is drafter-heavy; code (3.8) less so — expect asymmetric gain.
**Gate:** round time prose ≤ 34.5 ms AND acceptance rate unchanged (±0.5%) AND hashes bit-exact. KILL if any stream-ordering hazard appears — don't debug races at 2am, the gate is the gate.

### D4. Paced L2 prefetch of next layer's expert tiles during gather_a/b (V4.1 recipe, ported) — **+2–4%, ~1.5h, low-medium risk**
Mechanism: routed experts 9.08 ms is bandwidth-bound on LPDDR5X; during the 2.3+2.1 ms gathers the memory system is idle-ish on the expert side. Issue `cp.async.bulk` / L2 prefetch hints for layer *n+1*'s top-k expert shards as soon as router *n* commits (router output known before gather completes). Cap prefetch bytes to avoid evicting activations.
**Gate:** routed experts ≤ 8.3 ms, no regression in gather time, hashes exact. KILL if L2 thrash shows up as gather_a > 2.5 ms.

**Skip tonight (D5+ backlog):** CUDA graphs for the GLM decode path — highest ceiling (kernel-launch overhead across ~10 kernels/layer × 45 layers) but capture with the PDL chain + dynamic top-k expert sets is a full day, not tonight. FP8 pack is a regression as configured; skip (below).
